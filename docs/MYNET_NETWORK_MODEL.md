# MyNet 网络模型与产品边界

## 文档目的

本文固定 MyNet 的产品语义和网络架构，作为 `mynet_api`、`mynet_gui`、`mynet_agent`、`mynet_openwrt` 和 `mynet_gnb` 后续设计的共同依据。

MyNet 面向小团队和小企业，提供低成本、可自托管的自动组网平台。用户不需要直接管理底层 VPN 配置；平台负责编排节点身份、数据面协议、路由、转发和网络服务。

## 核心定义

### 租户是真实的隔离边界

租户是 MyNet 中真实存在的组织或网络空间，隔离用户、节点、地址、路由、服务、权限和配额。不同租户完全隔离；好友关系和用户邀请本身不建立跨租户通信。

用户不是租户，也不存在个人租户。个人用户只是加入某个租户并使用其中的组网能力。用户可以拥有自己的节点，但节点属于当前租户空间。

### 私网不是独立业务实体

私网不是必须创建和保存的独立对象。私网是一个逻辑概念，表示在某个租户的成员关系、节点关系、路由和访问策略作用下形成的可通信范围。

因此，用户加入租户后，租户内可通信的节点集合就是他感受到的私网；企业员工、节点和服务形成企业私网；好友授权后的可达节点和网络形成共享访问视图。私网会随着成员、节点、路由和授权变化而变化。

实现上应以租户、用户、节点、节点池、连接、路由、服务和策略为实体，不强行增加一个“私网表”。

## 用户与企业

租户是企业级的治理与隔离空间，好友是用户级关系。不存在“朋友租户”这一租户类型。朋友可以创建或加入一个租户，并在有邀请权限时邀请用户加入；接受邀请加入的是该租户，而不是朋友的个人网络空间。

普通用户可能有意选择，也可能通过默认入口或邀请码加入某个租户，然后启动节点池、注册自己的设备、建立获准的连接并访问授权网络服务。注册时填写邀请码的制度保留；邀请码的加入范围和权限按租户规则处理。

企业创建并拥有独立租户。管理员决定谁可加入、员工能否自由组网、每人可有多少节点池和节点、是否允许实体网络接入，以及哪些节点、网段和服务可以互通。

自由组网表示用户可以在租户许可和配额内扩展自己的节点、节点池和连接，不等于租户内所有用户的节点自动全互通。自己的节点默认互通；开放空间中，好友之间仍需逐节点建立获准的通信关系。企业管理员可以另行启用有规模限制的企业自动组网。

## 节点池

节点池是用户在租户中可申请、购买和管理的 MyNet 节点资源单元，不代表实体网络，也不代表新租户。

默认节点池可提供六个 IP 和六个节点额度。用户可购买更多节点池；例如十个节点池可提供约六十个节点额度，实际数量由租户和计费策略决定。

节点池可包含用户自己的电脑、服务器、OpenWrt 设备、云主机和其他 MyNet peer。朋友的实验室、办公室或其他第三方实体网络不属于用户的节点池。

配额建议分为：

- 租户配额：租户允许的节点池、节点和网络接入点总量。
- 用户配额：租户内某用户可使用的节点池和节点数量。
- 节点池配额：单个节点池的 IP、节点、连续地址和高级能力。

## 节点和实体网络

MyNet 节点运行 GNB、WireGuard 或其他受支持的数据面，可承担普通终端、转发节点、实体网络网关、出口节点或服务提供节点的角色。

实体网络是节点所在位置之外的真实网络，例如家庭局域网、办公室网段、朋友实验室或云私网。实体网络仍属于其原所有者。

## Peer 网关和远程网络

要访问朋友的实验室，朋友需在实验室内部安装 MyNet peer 作为网关：

```text
你的节点 → MyNet 连接 → 朋友实验室的 peer 网关 → 实验室内网
```

网关代表实验室接入 MyNet，负责转发、回程路由、防火墙和状态上报。访问者得到的是被授权的访问权，不是实验室网络的所有权或管理权。

## 通信关系

MyNet 支持：

```text
节点 ↔ 节点
节点 ↔ 网络
网络 ↔ 网络
```

三者都依赖数据面连接、节点内路由、系统 IP 转发、防火墙、回源能力和访问授权。

## 自动组网

企业范围的自动组网通常面向经过认证的企业网络，并由租户管理员按策略启用。“认证”的具体流程和资格标准待设计，本文件不预设认证方式。

启用后，在获准范围内自动登记节点关系、生成路由并下发配置，让员工节点按企业策略通信。注册、地址分配、身份登记和配置同步可以自动化，但不能据此推导出全租户互通授权。

自动组网必须有规模限制。节点与连接增长会扩大 GNB 的 `route.conf` 和配置分发量；不能无限生成全量节点关系。具体节点数、路由条目数、配置大小及设备承载上限需要实测后确定，目前不设未经验证的数字。

后续实现应在扩容或启用前检查容量，并在超限时给出明确反馈，避免静默生成无法承载的配置。该约束属于配置编排和容量管理；复杂自动选路交给各数据面生态。

租户管理员可以限制成员互通、每人节点数量、节点池数量、实体网络接入、转发/出口能力和服务范围。购买更多节点池不绕过租户权限或自动组网规模限制。

## GNB、WireGuard 和混合数据面

同一租户、同一逻辑私网中可以同时存在 GNB 和 WireGuard 节点。平台不把私网强制限制为单一协议，但建议同一组网场景尽量选择统一数据面。

不同数据面不能假设可以直接建立协议级连接。跨协议通信必须通过同时支持两种数据面的节点进行节点内路由和转发：

```text
GNB 节点 → 双数据面转发节点 → WireGuard 节点
```

agent 应使用统一驱动接口：

```text
DataPlaneDriver
 ├── GNB driver
 └── WireGuard driver
```

驱动负责协议差异，API、GUI 和业务模型只表达节点、连接、路由和访问意图。

## 网络服务和 Proxy

租户或共享网络可以发布 DNS、代理出口、企业内网站点、文件服务、监控服务和其他内部 API。服务需要记录提供节点、访问范围、方向、转发需求和健康状态。

Proxy 是节点转发能力的一种策略应用：

```text
客户端节点 → 代理/出口节点 → 外部目标网络或互联网
```

它可实现出口选择、目标网段访问、DNS 分流、企业出口和远程网络访问。对用户统一归入“加速”，其中 Proxy 对应“路径加速”。技术文档和实现仍保留 Proxy 名称，准确说明流量经过所选节点转发及出口的变化。

## 密钥与配置恢复

用户可以不理解协议细节，但必须知道节点密钥是设备身份的一部分。平台应提供公钥和指纹查看、私钥安全保存提示、配置备份、密钥备份、节点恢复、密钥轮换以及导入导出校验。

私钥不得进入普通 API 响应、邮件或日志。备份包可包含节点身份、密钥、协议、租户和节点标识、配置、版本及校验信息。

## Gateway

gateway 是边缘接入和转发层，不是业务权威。它用于就近接入、骨干线路访问核心 API、承载节点长连接、转发请求和维护连接状态。租户权限、用户授权、节点身份和业务规则仍由 API 与节点身份体系负责。

## OpenWrt

OpenWrt LuCI 是正式产品界面。性能足够的设备使用：

```text
LuCI → mynetd → mynet → GNB/WireGuard
```

弱设备可使用：

```text
LuCI/Lua → OpenWrt 原生能力 → GNB/WireGuard
```

两种模式都应提供注册、配置同步、启停、密钥、路由、转发、回源、状态、诊断和恢复能力。Lua 可以是轻量执行器，但不能形成第二套租户和业务后端。

## UTC

UTC 当前暂不实现，也不进入当前产品承诺；Proxy 的路径转发实现属于当前 v1 范围。架构应保留分层：

```text
租户和网络关系 → GNB/WireGuard 数据面 → UDP/TCP/UTC/Relay 传输层
```

未来 UTC 应同时服务 GNB 和 WireGuard，而不是成为第三种私网协议。

## 未来构思：用户贡献加速能力

本节是未来方向，不代表当前已实现，也不改变 UTC 暂缓的决定。

用户未来可以自愿贡献自己的设备，为其他获准用户提供加速能力，包括跨境连接场景。产品统一使用“加速”名称，分为：

| 产品类型 | 技术对应 | 作用 |
| --- | --- | --- |
| 协议加速 | UTC | 通过传输方式适配改善连接体验，未来需支持 GNB 和 WireGuard |
| 路径加速 | Proxy | 通过贡献节点转发流量，使用该节点提供的路径或出口 |

“加速”是产品分类，不保证每条连接都更快；效果取决于路径和节点条件。界面应明确所选节点、流量转发方式及出口变化。

用户贡献 Proxy 节点属于未来构思；Proxy 本身是当前 v1 的实现范围。贡献节点的发布、使用授权、资源限额、撤回、质量评估和可能的收益规则尚待设计。贡献行为不改变节点所有权，也不自动开放贡献者的局域网。此构思不引入跨租户互通；若未来需要跨租户服务，须另行定义边界，不能通过好友关系或贡献行为隐式打通。

本阶段不承诺贡献市场、结算或自动调度，也不自研大规模运营商网络优化。

## 最终产品定位

MyNet 是一个以租户为隔离边界的组网平台：用户加入租户，在其中管理自己的节点和节点池；用户按租户规则连接节点、实体网络和网络服务，认证企业网络可启用有规模限制的自动组网；同一租户可同时使用 GNB 和 WireGuard；实体网络通过其所有者部署的 peer 网关接入；GUI 隐藏底层复杂配置，同时对密钥、备份和恢复保持透明。

> **MyNet 让用户加入一个隔离的网络空间，在其中管理自己的节点，并按照租户规则自动连接节点、实体网络和网络服务。**
