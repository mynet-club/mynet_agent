# 本机 WebUI 可用性设计

> 对象：`mynetd` 内嵌 webui（`mynetd/localapi/webui/`），本机桌面 / Mac / 调试场景。
> 参照：LuCI 的 `index.htm`（健康检查聚合 + 分区表格）与 `service.htm`（状态/网络/对端/日志/诊断 五页签）。
> 约束（用户 2026-09-25）：交互在**本机 web 页面**；OpenWrt 走 LuCI；**绝不做进 TUI**。
> `mynet` CLI 只提供非交互原语，本面是它的薄封装。

## 0. route.conf 约定（用户设计意图，2026-09-25 钉死）

### 0.1 为什么「凡节点都 /32」

> 「所有的生成节点的系统路由，都是通过**第一个节点的 gnb 硬件**走的。
> 我这么设计就是想，如果一台设备上运行两个 gnb（gnb1、gnb2）时，
> 对不同的节点就有不同的**精准路由**，不会被 /24 淹没。」

翻成路由语义：

```
一台机器上并行两个 gnb 实例：

  gnb1  tun=g_tun1  本机 10.0.0.15   peers: 10.0.0.16, 10.0.0.17
  gnb2  tun=g_tun2  本机 10.0.1.15   peers: 10.0.1.16, 10.0.1.17

OS 路由表（全部 /32，各指各的 tun）：
  10.0.0.16/32 → g_tun1
  10.0.0.17/32 → g_tun1
  10.0.1.16/32 → g_tun2
  10.0.1.17/32 → g_tun2
```

若任何一处写成 /24（`10.0.0.0/24 → g_tun1`），同段里属于 gnb2 的对端
就会被**整段吞掉**，流量进错隧道。**/32 是双实例精准路由的前提**，
不是分配偷懒。因此：

- overlay 节点地址**一律 /32**，哪怕它们碰巧落在同一个 /24 里
- 系统路由（apply）对每个对端装一条 **/32 → 本 gnb 的 tun**
- route.conf 里每个节点一条**主机行**，第一条是**本机**（第一个节点）

### 0.2 行约定

1. **第一条 = 本机节点** —— 本 gnb 实例的「第一个节点」。
   gnb 靠 `uuid == local_uuid` 那行设 tun 地址
   （`gnb_conf_file.c:938-946`：`0 != p[3] && 0 == node->tun_addr4.s_addr`）；
   本机 nodeid 缺失直接 `exit(1)`（:1075-1078）。
2. **每个对端一条记录**（主机行 /32），不管是否同一 /24。
3. **按 NodeID 分组** —— 同一 nodeid 可有多行，但**默认只有主机行**：
   - 主机行（IP 末段 ≠ 0）：该节点 tun 地址，每节点**恰好一条**
   - 网段行（IP 末段 = 0）：**仅当**该节点额外公告了背后的子网
     （网关节点挂 LAN 时）。overlay 自身**绝不用网段行**
     ——那会把范围放大，正是「被 /24 淹没」要避免的事。

行格式（`gnb_conf_file.c:919-928`）：`<nodeid>|<ip>|<点分掩码>`，掩码是点分十进制不是 CIDR。

### 0.3 已知实现缺口（需修）— `RenderGNBRouteConf`（`mynet/driver/gnb.go:663`）

| 约定 | 现状 | 后果 |
|---|---|---|
| 第一条 = 本机 | 按 `g.Nodes` 迭代序 | 不保证本机在前 |
| 每节点一条主机行 | 依赖 publisher 放进 Nodes | 缺测试钉「N 对端 = N+1 行」 |
| 同 nodeid 可另有网段行 | `seen[nodeID]` 一节点只出一行 | 网关节点的 LAN 行被吞 |
| 去重键应为 nodeID+cidr | 去重键是 nodeID | 同 id 不同前缀二选一 |

**注意**：网段行是**可选增强**（网关公告 LAN），主路径是
「N+1 条 /32 主机行」。修渲染器时主机行/网段行要分槽，
不能只把去重键改成 (nodeID,cidr)——否则末段≠0 的第二行会被 gnb
当网段入 ring（`gnb_conf_file.c:956-958`）。

## 1. 状态机：从「没装」到「跑起来」

状态由**磁盘产物 + 进程 + 内核**共同判定，不靠内存计数器
（CPI-68 教训：落盘结果比命令退出码可信）。

```
                    ┌──────────────┐
           开箱     │ UNINSTALLED  │  无 gnb 二进制 / 无 systemd 单元
                    └──────┬───────┘
                           │ [安装]
                    ┌──────▼───────┐
           装上了   │ INSTALLED    │  有二进制，无 conf/mynet.conf
                    └──────┬───────┘
                           │ [配置]（向导：登录→选节点→下载）
                    ┌──────▼───────┐
           配好了   │ CONFIGURED   │  mynet.conf + bundle + var/gnb/node.conf
                    └──────┬───────┘
                           │ [启动] = service start + apply --auto
                    ┌──────▼───────┐
           起来了   │ RUNNING      │  进程活 + tun 有 IP + 对端 /32 路由已装
                    └──────┬───────┘
                           │ 配置变更 / 对端变更
                    ┌──────▼───────┐
                    │ RELOADING    │  reload（Stop+Start）+ 重装路由
                    └──────┬───────┘
                           │
           ┌───────────────┼───────────────┐
           ▼               ▼               ▼
     ┌──────────┐   ┌───────────┐   ┌──────────┐
     │ RUNNING  │   │ DEGRADED  │   │  FAILED  │
     └──────────┘   └───────────┘   └──────────┘
      全绿           进程在，但       启动失败 /
                     路由缺 / 对端    配置非法 /
                     不可达           密钥不匹配
```

### 1.1 判据表（每条都要可脚本核对）

| 状态 | 判据（须全部满足） | 探测来源 |
|---|---|---|
| UNINSTALLED | `gnb` 不在 PATH 且不在 install 足迹 | `which gnb` / `mynet driver list` |
| INSTALLED | 二进制在，但 `conf/mynet.conf` 不存在 | 文件存在性 |
| CONFIGURED | `mynet.conf` ∧ `var/bundle.json` ∧ `var/gnb/node.conf` 非空 | wizard/state 同源 |
| RUNNING | 进程活 ∧ tun 有本机 overlay IP ∧ 每个对端 /32 路由存在 | `service status` + `ifconfig`/`ip addr` + `route get` |
| DEGRADED | 进程活，但上述路由/IP/对端任一缺失 | 逐项 diff |
| FAILED | `service start` 非零，或启动后探测窗口内无进程 | Start 的 waitAlive |

### 1.2 「状态一言之」（顶部横幅，LuCI health_issues 同款）

一句人话 + **一个**主按钮。永远先说「现在缺什么」，再说「怎么补」。

| 状态 | 一言之 | 主按钮 | 次按钮 |
|---|---|---|---|
| UNINSTALLED | 未安装 gnb 驱动 | 安装 | 查看依赖 |
| INSTALLED | 已安装，尚未配置节点 | 去配置 | 卸载 |
| CONFIGURED | 已配置 10.0.0.15，隧道未启动 | 启动隧道 | 重新配置 |
| RUNNING | 运行中 · utun4 · 10.0.0.15 · 对端 1/1 在线 | 重启隧道 | 停止 |
| DEGRADED | 进程在，但到 10.0.0.16 的路由缺失 | 修复路由 | 停止 |
| FAILED | 启动失败：gnb 退出且无进程（查 node.conf/密钥） | 重试启动 | 看日志 |

## 2. 信息架构（单页五区，状态从上到下由粗到细）

对齐 LuCI `index.htm` 的分区，但收成**一屏**——本机 webui 不是路由器控制台，
不需要五页签，需要的是「一眼知道能不能用」。

```
┌────────────────────────────────────────────────────────┐
│ ① 状态横幅     ● 一言之                    [主按钮][次]  │
├────────────────────────────────────────────────────────┤
│ ② 节点身份     NodeID · overlay · 接口 · MTU · endpoint │
├──────────────────────────┬─────────────────────────────┤
│ ③ 安装与配置             │ ④ 运行                       │
│   gnb ✓ gnb_ctl ✓        │   进程 pid=… 运行 3h12m      │
│   单元 mynet_gnb ✓        │   tun utun4 10.0.0.15/32    │
│   配置 mynet.conf ✓       │   RX 840 · TX 840           │
│   bundle ✓ (16:19)       │   [启动][重启][停止]          │
│   [安装][配置向导][刷新]  │                              │
├──────────────────────────┴─────────────────────────────┤
│ ⑤ 对端与路由                                             │
│   route.conf: 本机行 + 每对端一行 /32                    │
│   OS 路由:  10.0.0.16/32 → utun4 ✓                      │
│   对端表:   nodeid | overlay | 链路态 | 延迟 | 路由 ✓     │
└────────────────────────────────────────────────────────┘
```

### 2.1 各区职责

**① 状态横幅** — 唯一强视觉。绿/黄/红点 + 一言之 + 主按钮。
主按钮在执行中变 spinner 并 disabled，完成后**就地刷新横幅**（不整页 reload）。

**② 节点身份** — 只读事实，回答「我是谁」：
`NODE_ID` / `overlay IP` / `BACK_PUB` 指纹前 8 位 / 隧道接口 / MTU / endpoint。
未配置时整区替换为「未配置」+ [去配置]。

**③ 安装与配置** — 逐项 ✓/✗ 徽章（LuCI `mn-dep-ok/fail` 同款）：

| 项 | 判据 | 缺失时按钮 |
|---|---|---|
| gnb 二进制 | `gnb -v` 或 install 足迹 | 安装 |
| gnb_ctl | 同上 | 随 gnb 装 |
| 托管方式 | systemd 单元 / launchd / 手工 | `mynet install` |
| mynet.conf | 文件非空 | 配置向导 |
| bundle.json | 文件非空 + checksum | 重新拉取 |
| var/gnb/node.conf | 文件非空 | refresh-config |

**④ 运行** — 只在 CONFIGURED 之后出现：
进程（pid、命令行、运行时长）、tun（真实接口名 + IP —— **不是**配置里的 `gnb_tun`）、
RX/TX、按钮组。

**⑤ 对端与路由** — 与 route.conf 约定直接对应：

```
本机  1353179228271167  10.0.0.15/32   utun4
对端  1005272783125838  10.0.0.16/32   链路=Direct  延迟=7ms  OS路由✓
```

每一行回答三件事：**配置里有没有、内核路由装没装、链路通不通**。
任一为否即 DEGRADED，横幅跟着变。

## 3. 按钮状态机

原则：**按钮的可见性、文案、enabled，本身就是状态的一部分**。
不要出现「点下去才知道不行」。

| 全局态 | 安装 | 配置向导 | 启动 | 重启 | 停止 | 修复路由 | 卸载 |
|---|---|---|---|---|---|---|---|
| UNINSTALLED | **主·可点** | 可点 | 禁用 | 禁用 | 禁用 | 禁用 | 隐藏 |
| INSTALLED | 隐藏（已装） | **主·可点** | 禁用 | 禁用 | 禁用 | 禁用 | 可点 |
| CONFIGURED | 隐藏 | 可点(重配) | **主·可点** | 禁用 | 禁用 | 可点 | 可点 |
| RUNNING | 隐藏 | 可点 | 禁用 | **可点** | 可点 | 隐藏 | 可点 |
| DEGRADED | 隐藏 | 可点 | 可点 | **主·可点** | 可点 | 可点 | 可点 |
| FAILED | 视缺口 | 可点 | **主·重试** | 禁用 | 禁用 | 可点 | 可点 |
| 执行中 | 全部 disabled + 当前按钮显示 ⟳ | | | | | | |

补充规则：

1. **执行中**（任意命令在飞）：所有动作按钮 `disabled`，当前按钮 spinner，
   横幅显示「执行中…」。完成后重新拉 `wizard/state` + `service status` 再画 UI。
2. **错误就地展示**：失败信息出现在横幅和对应按钮下方（红字），不要只进 `<pre>` 日志。
   日志区保留完整 stdout/stderr（已脱敏）。
3. **危险操作二次确认**：停止、卸载 —— `confirm()`，文案说清后果
   （「停止后 overlay 立刻不可达」）。
4. **主按钮唯一**：任一时刻只有一个 primary（视觉权重最高），其余是 secondary。

## 4. 数据流

```
浏览器 ──GET──► /api/v1/wizard/state     磁盘产物（登录/配置/bundle）
       ──GET──► /api/v1/metrics          进程/tun/peers/rx/tx
       ──POST─► /api/v1/command          装/配/起/停/apply（白名单）
                    │
                    ▼
                 mynet CLI（薄封装，口令走 stdin）
```

新增（本设计要求补的）：

| 端点 | 作用 |
|---|---|
| `GET /api/v1/wizard/state` **扩展** | 增加 `installed` / `process_running` / `tun_iface` / `overlay_ip` / `routes_ok` / `peers[]` / `one_line` / `primary_action` |
| 或 `GET /api/v1/node-status` | 若不想把 wizard/state 撑太大，单独出一条「本机节点状态」 |

状态计算放在 **Go 侧一次算完**（`mynetd`），浏览器只渲染。
不要让前端拼状态机 —— 那会和 CLI 的判据漂移。

## 6. 多实例系统面（二期，一期先留钩子）

### 6.1 命题

一台机跑 gnb1 + gnb2 时，**配置按节点为根组织（route.conf 不变）**，
所有实例在**系统层**汇聚到同一处。冲突点不在配置，在内核与守护：

### 6.2 共享资源清单

| # | 资源 | 撞车点 | 归属/隔离 | 一期钩子 |
|---|---|---|---|---|
| 1 | **内核路由表** | `ip route add/del` 同一张 RIB | /32 精确 + 按节点记账；删除只删本节点名下 | ✅ 禁 `flush dev`，按计划目的地删 |
| 2 | **防火墙** | iptables/nft/pf 同表/锚 | 规则锚定 tun 名/实例标记 | ✅ 不写裸 `-F` |
| 3 | **NAT/转发** | `ip_forward` 全局 | 开关幂等共用；masq 按 oifname 各写 | 幂等即可 |
| 4 | **进程生命周期** | 多 gnb、pid、gnb.map | 每 conf 目录一套 pid/ctl；systemd 模板单元 | ✅ pid 跟 conf 走，禁按名 kill |
| 5 | **tun 接口** | 名字/地址/MTU | Linux ifname 各起各的；darwin utunN → IP 反查 | 已有 resolveDevice |
| 6 | **UDP 监听端口** | 同端口 bind 失败 | 每实例分配端口 | 二期分配 |
| 7 | **overlay IP 唯一性** | 同 /32 两节点 → 精确撞车 | 分配侧唯一；apply 检测并报冲突 | 二期检测 |
| 8 | **密钥/身份** | security/ 与 ed25519/ | 每节点一棵 | 已隔离 |
| 9 | **日志** | 多实例交织 | 每实例独立日志文件 | 二期 |
| 10 | **指标/心跳** | 聚合口径 | 按 node_id 分列 | 二期 |
| 11 | **开机自启** | 多 systemd/launchd 单元 | 模板单元或每实例一单元 | 二期 |
| 12 | **Web 管理界面** | 单节点假设贯穿 | 实例列表 + 焦点 + 每实例状态机 | 一期按单实例做，状态机按实例参数化 |
| 13 | **升级/卸载** | 共用二进制 | 装全实例共用；卸载遍历 | 二期 |
| 14 | **cgroup/资源** | 多进程争抢 | systemd 天然隔离 | 不管 |

### 6.3 为什么 /32 让二期变便宜

```
gnb1  tun=g_tun1  peers: 10.0.0.16/17     → 10.0.0.16/32 → g_tun1
gnb2  tun=g_tun2  peers: 10.0.1.16/17     → 10.0.1.16/32 → g_tun2
```

/32 保证互不淹没、冲突可见（精确撞车，不是 /24 静默吞）。
编址模型不用回头改，二期只做「归属记账 + 范围化清理」。

### 6.4 一期必须留下的三个钩子（否则二期要改契约）

1. **apply 删除按「本计划声明过的目的地」**，禁止 `ip route flush dev …`
2. **防火墙规则锚定 tun/实例标记**，禁止裸 `iptables -F`
3. **pid/ctl 路径跟 conf 目录**，禁止按进程名 kill（AGENTS.md §3 红线）

## 8. 明确不做

- 不做 TUI（用户明令）
- 不把 token/口令放进浏览器（已有约定）
- 不在前端重算状态机
- 不把「网段 on-link」当目标 —— 节点一律 /32，对端靠显式路由
- 一期不做多实例 UI/端口分配（见 §6）
